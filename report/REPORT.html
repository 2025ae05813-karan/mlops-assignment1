1. Introduction & Objective

Cardiovascular disease is a leading cause of mortality, and early risk identification supports timely clinical intervention. This project builds a binary classifier that predicts the presence of heart disease from 13 routine patient measurements, and — more importantly for this course — wraps that model in a complete MLOps lifecycle: reproducible data processing, experiment tracking, automated testing, CI/CD, containerized serving, Kubernetes deployment, and monitoring.

The emphasis is on production readiness: every artifact is regenerated by code, the pipeline fails loudly on errors, and the model serves identically in an isolated container.

3. Dataset & Exploratory Data Analysis

Source: UCI Machine Learning Repository, Heart Disease dataset (ID 45), Cleveland subset — 303 patients, 13 features + target.

Cleaning steps (src/data_loader.py): - The raw files are header-less and use ? for missing values → converted to NaN and all columns coerced to numeric. - The original target num is a 0–4 severity score → binarized: 0 = no disease, 1–4 = disease. - Exact duplicate rows removed. - Imputation/scaling are deliberately not done here; they live in the model pipeline (fit on training folds) to prevent data leakage.

Resulting dataset: 303 rows, 6 missing cells (in ca, thal), class balance 164 no-disease / 139 disease (~54% / 46%) — well balanced.

Class balance

The near-even split means accuracy is a usable headline metric, but we still report precision, recall, and ROC-AUC because recall (catching true cases) is clinically most important.

Numeric feature distributions

Diseased patients tend to show lower maximum heart rate (thalach) and higher ST depression (oldpeak), consistent with clinical expectations.

Categorical feature distributions

Chest-pain type (cp), exercise-induced angina (exang), number of major vessels (ca), and thal separate the classes clearly.

Correlation heatmap

The strongest positive correlations with the target are thal (0.53), ca (0.46), exang (0.43), and oldpeak (0.42); thalach is the strongest negative (−0.42). No pair of predictors is collinear enough to require removal.

4. Feature Engineering & Modeling

Preprocessing (src/preprocess.py)

A single scikit-learn Pipeline wraps a ColumnTransformer: - Numeric (age, trestbps, chol, thalach, oldpeak): median imputation → standard scaling. - Categorical (sex, cp, fbs, restecg, exang, slope, ca, thal): most-frequent imputation → one-hot encoding (handle_unknown="ignore").

Bundling transforms into the pipeline guarantees that training and serving apply identical logic and that statistics are learned only from training data.

Models & tuning (src/train.py)

Two classifiers were trained and tuned with GridSearchCV + 5-fold stratified cross-validation, scoring on ROC-AUC:

Model Search space
Logistic Regression C ∈ {0.01, 0.1, 1, 10}, solvers {lbfgs, liblinear}
Random Forest n_estimators ∈ {200, 400}, max_depth ∈ {None, 5, 10}, min_samples_leaf ∈ {1, 2, 4}

Data was split 80/20 (stratified, seed 42). Each tuned model was evaluated on the held-out 61-row test set.

Results

Model CV ROC-AUC Test Acc Precision Recall F1 Test ROC-AUC
Logistic Regression (selected) 0.9025 0.8852 0.8387 0.9286 0.8814 0.9665
Random Forest 0.8996 0.8525 0.8065 0.8929 0.8475 0.9545

Selection: Logistic Regression was chosen on the highest cross-validated ROC-AUC. It also delivers the best recall (0.93) — the priority for a screening model — while remaining interpretable.

  • Artifact: models/model.joblib — the full preprocessing + model pipeline, serialized with joblib. models/model_metadata.json records the selected model, tuned params, feature schema, seed, and all candidate metrics.
  • Dependencies: pinned in requirements.txt (and environment.yml).
  • Verification: a clean virtual environment was created, dependencies installed solely from requirements.txt, and the full pipeline re-run — it reproduced the exact metrics and sample prediction. See REPRODUCIBILITY.md.

7. CI/CD & Automated Testing

Tests (tests/, 26 total): - test_data.py (11) — raw loading, ?→NaN, target binarization, dedupe, feature split, imputation, scaling, full-pipeline fit/predict. - test_model.py (7) — ≥2 models present, valid grids, metric correctness, estimator learning, predict_proba availability. - test_api.py (8) — health, predict (prediction + confidence), input validation (422), metrics endpoint.

Pipeline (.github/workflows/ci.yml): three gated jobs — lint (ruff) → test (pytest + JUnit) → train (MLflow + artifact uploads). The pipeline fails on any lint or test error (verified non-zero exit codes) and uploads the test report, model, plots, and MLflow runs as artifacts.

A successful run of the pipeline on main: all three jobs — Lint (ruff), Unit tests (pytest), and Train & publish model — pass, producing four uploaded artifacts.
